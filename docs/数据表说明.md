# 数据表说明

所有表位于 `data/`，格式为 JSON，Godot 4 运行时用 `FileAccess` + `JSON.parse_string` 直接读取。
**代码里不允许出现任何数值**，调平衡只改这里的文件。

## 文件清单

| 文件 | 内容 | 行数 |
|---|---|---|
| `balance.json` | 全局系数、经济参数 | — |
| `chassis.json` | 底盘 | 3 |
| `engines.json` | 引擎 | 4 |
| `cunits.json` | C 装置 | 2 |
| `weapons.json` | 武器（主炮/副炮/SE） | 8 |
| `enemies.json` | 敌人 | 5 |
| `items.json` | 道具与弹药 | 5 |
| `player.json` | 玩家角色 | 1 |

除 `balance.json` 外，其余表统一结构：`{ "_comment": "...", "rows": [ {...} ] }`。
`_comment` 只给人看，加载器必须忽略。

## 字段定义

### chassis.json（底盘）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一，前缀 `c_` |
| weight | int | 自重，计入载重 |
| armor | int | 装甲吸收池，归零则战车损坏 |
| def | int | 固定减伤，参与伤害公式 |
| slots | array | `{type, size}`，type ∈ main/sub/se，size ∈ S/M/L |
| terrain | array | 可通行地形：road / sand / mountain |
| price | int | 购买价，0 表示初始车 |

### engines.json（引擎）

| 字段 | 类型 | 说明 |
|---|---|---|
| output | int | 载重上限，同时参与机动计算 |
| can_buy | bool | false 表示只能通过掉落获得 |

### cunits.json（C 装置）

| 字段 | 类型 | 说明 |
|---|---|---|
| acc_bonus | int | 命中修正，直接加到命中率 |
| eva_bonus | int | 回避修正，直接减对方命中率 |

### weapons.json（武器）

| 字段 | 类型 | 说明 |
|---|---|---|
| type | string | main / sub / se，必须与槽位一致 |
| size | string | S / M / L，必须 ≤ 槽位 size |
| atk | int | 攻击力 |
| ammo | int | 单场战斗可用弹数，战后不自动补 |
| acc | int | 命中基准 |
| aoe | bool | 是否范围攻击（同时打全部敌人） |

### enemies.json（敌人）

| 字段 | 类型 | 说明 |
|---|---|---|
| hp | int | 生命，装甲归零后才开始扣 |
| armor | int | 吸收池；**有效血量 = armor + hp** |
| def | int | 固定减伤 |
| acc | int | 命中基准（不再叠加 C 装置） |
| eva | int | 回避 |
| spd | int | 机动，决定行动顺序 |
| is_vehicle | bool | 是否适用装甲规则 |
| is_bounty | bool | 是否赏金首（决定能否领赏、是否只出现一次） |
| ai | string | aggressive / random / static |
| drops | array | `{item, qty, rate}`，item 可为道具 id 或引擎 id |

### items.json（道具）

| 字段 | 类型 | 说明 |
|---|---|---|
| type | string | material（只可卖）/ repair（补装甲）/ ammo（补弹） |
| sell_price | int | 出售价 |
| effect | object | repair → `{armor}`；ammo → `{slot, qty}` |

## 公式（全部从 balance.json 取系数）

```
命中率   HIT  = clamp(武器.acc + C装置.acc_bonus - 目标.eva, 30, 99)
基础伤害 BASE = 攻击力 - 目标.def × defense_factor(0.5)
伤害     DMG  = max(1, round(BASE × rand(1 ± damage_variance)))
暴击           = 5% 概率 × crit_multiplier(1.5)
装甲结算       先扣 armor，超出部分扣 hp
机动     SPD  = clamp(round(引擎.output / 整车总重 × 20), 5, 40)
```

## 改装校验（三关全过才能出车）

```gdscript
func can_deploy(build: Dictionary) -> Array[String]:
    var errors: Array[String] = []
    var chassis = GameData.chassis[build.chassis_id]
    var engine = GameData.engines[build.engine_id]

    # 1. 槽位数量与尺寸
    var used := { "main": 0, "sub": 0, "se": 0 }
    for w in build.weapons:
        var weapon = GameData.weapons[w]
        used[weapon.type] += 1
        var fitted := false
        for slot in chassis.slots:
            if slot.type == weapon.type and SIZE_ORDER[weapon.size] <= SIZE_ORDER[slot.size]:
                fitted = true
        if not fitted:
            errors.append("%s 没有可用槽位" % weapon.name)
    # 2. 载重
    var total := chassis.weight + engine.weight + GameData.cunits[build.cunit_id].weight
    for w in build.weapons:
        total += GameData.weapons[w].weight
    if total > engine.output:
        errors.append("超载 %d / %d" % [total, engine.output])
    return errors
```

## 数值校验示例（改表后必须能对上）

**① 初始吉普 vs 赏金首「赤蝎」——预期失败**

| 项 | 计算 |
|---|---|
| 吉普配置总重 | 380 + 180 + 60 + 150 + 45 = **815** ≤ 900 ✓ |
| 机动 | 900 / 815 × 20 = 22（先手，赤蝎 20） |
| 75mm 伤害 | 85 − 25×0.5 = 72.5 → **73** |
| 75mm 命中 | 75 + 5 − 15 = 65% |
| 每轮期望 | 73 × 0.65 ≈ 47 |
| 赤蝎有效血量 | 160 + 220 = **380** |
| 主炮 8 发总期望 | 47 × 8 = 376，差一点，还得靠机枪（约 7/轮） |
| 赤蝎反击 | 38 − 0 = 38 伤害 × 77% ≈ **29/轮**；吉普有效血量 120+40=160，约 5 轮被打穿 |

结论：火力勉强够，但撑不到打完 → **刻意设计成打不过**，逼玩家先去升级。1000 场实测胜率 20.2%。

**② 装甲卡车 + 105mm vs 赤蝎——预期稳定**

| 项 | 计算 |
|---|---|
| 卡车配置 | 720 + 320 + 60 + 260 + 80 = **1440** ≤ 1500 ✓（装 SE 会变成 1560 超载） |
| 机动 | 1500 / 1440 × 20 = 21 > 20，仍然先手 |
| 105mm 伤害 | 140 − 12.5 = 128，命中 70 + 5 − 15 = 60%，期望 77/轮 |
| 6 发总期望 | 461 > 380 → 约 5 发击破 |
| 赤蝎反击 | 38 − 2 = 36 × 77% ≈ 28/轮 × 5 轮 = 140 < 200 装甲 ✓ |

结论：弹药刚好够、装甲刚好够，赢但很紧——这就是想要的节奏。1000 场实测胜率 81.6%。

## 加载方式（Godot 4）

```gdscript
# scripts/autoload/game_data.gd
extends Node

var balance: Dictionary
var chassis := {}
var engines := {}
var cunits := {}
var weapons := {}
var enemies := {}
var items := {}
var player := {}

func _ready() -> void:
    balance = _read("res://data/balance.json")
    chassis = _index("res://data/chassis.json")
    engines = _index("res://data/engines.json")
    cunits  = _index("res://data/cunits.json")
    weapons = _index("res://data/weapons.json")
    enemies = _index("res://data/enemies.json")
    items   = _index("res://data/items.json")
    player  = _index("res://data/player.json")

func _read(path: String) -> Dictionary:
    return JSON.parse_string(FileAccess.get_file_as_string(path))

func _index(path: String) -> Dictionary:
    var out := {}
    for row in _read(path).get("rows", []):
        out[row["id"]] = row
    return out
```

## 跑数值（M0 自动对战）

```powershell
# user:// 默认落在真实 AppData，本机写入会失败并让 Godot 崩溃，所以把 APPDATA 指到工作区
$env:APPDATA="<工作区>\tools\appdata"
godot --headless --path metalmax_like -s res://scripts/tools/sim_battle.gd -- --runs=1000
```

输出打到 stdout，同时落盘到 `user://sim_report.txt`（Windows 下 Godot 是 GUI 子系统程序，stdout 可能被终端吞掉）。
`--runs=` 可改场数；结果里出现 `FAIL` 就说明改表把某一档平衡改坏了。

## 数据完整性规则（写工具或单测时逐条检查）

1. 每张表 `id` 唯一，前缀符合 `c_ / e_ / cu_ / w_ / en_ / it_ / p_`
2. `enemies.drops[].item` 必须能在 `items` 或 `engines` 里找到
3. 不存在底盘装不下任何武器的组合（每套底盘至少有一个 S 槽）
4. 每档引擎至少有一辆底盘能装配出可用配置（否则该引擎无意义）
5. 所有系数只能来自 `balance.json`；表里出现裸数字即视为 bug
6. 当前数值已过 M0 校准，**每次改表都要重跑 `sim_battle.gd`**。基准：初始吉普打赤蝎 20.2%、卡车+105 81.6%、沙蝎×2 2.9 轮（门槛见 GDD 第 10 章）
